# 2026-04-11 工作日志

## 今日目标

将 Astro 默认项目改造成一个基于 Sanity 数据源的 B2B 太阳能产品展示站，并对首页进行数据层、样式层和业务组件层拆分，降低 `src/pages/index.astro` 的复杂度。

## 工作日志

### 1. Sanity 数据接入

- 在 `astro.config.mjs` 中接入 `@sanity/astro`。
- 使用 `sanity:client` 从 Sanity 的 `production` dataset 获取首页数据。
- 在 `src/lib/homeData.ts` 中整理首页 GROQ 查询，覆盖以下业务数据：
  - `siteSettings`
  - `productCategory`
  - `product`
  - `application`
  - `caseStudy`
  - `faq`
- 移除了首页本地 fallback 业务数据。
- 数据获取失败时，页面显示明确错误状态，不再静默使用默认内容。

### 2. 首页白屏问题处理

- 排查 `localhost:4321` 白屏问题。
- 发现 Sanity 请求受到本地代理环境变量影响：

```text
HTTP_PROXY=http://127.0.0.1:7897
HTTPS_PROXY=http://127.0.0.1:7897
```

- 当该本地代理不可用时，Sanity 请求失败或等待，进而影响页面渲染。
- 后续将页面行为调整为：接口失败时显示错误信息，而不是 fallback 或白屏。

### 3. 产品图片渲染修复

- 根据 Sanity 返回数据结构，修正产品图片查询和渲染逻辑。
- 产品图片查询兼容以下字段：
  - `image`
  - `mainImage`
  - `gallery[0]`
  - `images[0]`
  - `category->image`
- 页面只使用 Sanity 接口返回的图片 URL，不使用本地占位图。
- 如果产品和关联分类都没有图片，则不渲染图片元素。

### 4. 首页数据逻辑拆分

- 新增 `src/lib/homeData.ts`。
- 将以下内容从 `src/pages/index.astro` 移入该文件：
  - 首页相关 TypeScript 类型定义
  - Sanity GROQ 查询
  - `fetchHomeData()` 数据获取方法
  - `imageUrl()` 图片 URL 辅助方法
- 拆分后，页面文件不再直接包含大量查询和类型定义。

### 5. 首页样式拆分

### 6. 首页业务组件拆分

## 遇到的问题

1. 首页白屏

   访问 `localhost:4321` 时页面最初出现白屏。排查后发现主要与 Sanity 请求失败或等待有关。

2. Sanity 请求受代理影响

   当前环境中 `HTTP_PROXY` 和 `HTTPS_PROXY` 指向 `127.0.0.1:7897`。当该代理不可用时，请求 Sanity 会失败，错误类似：

```text
tunneling socket could not be established, cause=connect EPERM 127.0.0.1:7897
```

3. 产品图片字段不一致

   页面最初只读取固定图片字段，和 Sanity 实际返回结构不完全一致，导致 product 图片没有显示。

4. 部分图片字段为空

   Sanity 中部分记录返回 `image: null`，需要兼容产品图、图库图和分类图多个来源。

5. 工具写入路径一度不正确

   项目后续目录从 `/Users/gaoxin/Documents/project/astro-hello-world` 变为 `/Users/gaoxin/Documents/project/solara-b2b-catalog`，旧路径导致部分文件写入和命令执行失败。

6. Vite optional dependency warning

   构建中出现过非阻断 warning，例如：

```text
react-compiler-runtime
lodash/startCase.js
```

   这些 warning 没有阻断构建。

## 解决方式

- 将 Sanity 请求失败时的行为改为显示明确错误状态。
- 移除本地业务 fallback，保证页面内容只来自接口数据。
- 扩展产品图片 GROQ 查询，兼容多个 Sanity 图片字段。
- 将首页拆成数据层、样式层和业务组件层。
- 清理未使用的 Astro starter 文件。
- 确认项目真实目录后，后续操作统一使用 `/Users/gaoxin/Documents/project/solara-b2b-catalog`。
